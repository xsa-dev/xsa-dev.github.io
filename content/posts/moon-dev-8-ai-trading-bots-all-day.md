## Введение

Современный алгоритмический трейдинг давно перешагнул эпоху простых скриптов на Python, запущенных в одном цикле `while True`. Сегодня перед разработчиками стоит задача построения настоящих **автономных распределенных систем**, где несколько специализированных AI-агентов работают параллельно: одни непрерывно ищут аномалии в стакане, другие гоняют бэктесты 24/7, третьи собирают funding rate на бессрочных фьючерсах (perps), а четвертые жестко контролируют риски.

В этом разборе мы изучим архитектуру системы из **8 параллельных AI-агентов**, разобранную в стриме алготрейдера Moon Dev, и разберем инженерные паттерны изоляции ролей, защиты капитала и минимизации латентности при работе с DEX (Hyperliquid).

## Ключевые инженерные принципы построения роя

### 1. Разделение контуров исследования и исполнения
Главная архитектурная ошибка монолитных торговых ботов — попытка совместить тяжелый анализ (бэктестинг сотен вариаций) и критический по времени контур исполнения ордеров в одном потоке. 
В описанной системе контуры разделены физически:
- **Research Loop (Агенты 1–4)** работает асинхронно, генерируя гипотезы, сохраняя их в базу данных SQLite/Postgres и обновляя конфигурационные файлы стратегий.
- **Execution Loop (Агенты 5–8)** читает валидированные конфигурации и работает с миллисекундными задержками, не отвлекаясь на логику обучения или генерации кода.

### 2. Модуль Risk Guardian как неснижаемый предохранитель
Никакой AI-агент не имеет права прямого доступа к полному депозиту без прохождения через `Risk Guardian`. 
- **Изоляция маржи**: Каждому агенту выделяется фиксированный суб-аккаунт или лимит (например, не более 5% от общего капитала).
- **Hard Stop-Loss**: Ордер отправляется на биржу сразу с прикрепленным жестким стоп-лоссом. Если сокет связи с биржей падает, стоп отрабатывает на стороне матчап-сервера биржи.

### 3. Преимущества работы с Perp DEX (Hyperliquid)
Перенос алготрейдинга с классических CEX на децентрализованные протоколы нового поколения (Hyperliquid) дает три критических преимущества:
1. **Прозрачность ончейн-ликвидности**: Доступ к реальному стакану и истории ликвидаций через быстрые WebSocket API без скрытых комиссий Maker/Taker-манипуляций.
2. **Отсутствие риска блокировки средств**: Негосударственный кастодиальный контроль через личные кошельки.
3. **Программируемость на Python/Rust**: Нативные SDK позволяют легко интегрировать LLM-агентов и автоматические генераторы стратегий.

## Пример базового контура риск-менеджмента на Python

Ниже приведен упрощенный паттерн защитного модуля, который проверяет сделку перед отправкой на Hyperliquid DEX:

```python
import logging
from dataclasses import dataclass

logging.basicConfig(level=logging.INFO)
logger = logging.getLogger("RiskGuardian")

@dataclass
class TradeOrder:
    symbol: str
    side: str  # 'BUY' or 'SELL'
    size: float
    entry_price: float
    stop_loss: float

class RiskGuardian:
    def __init__(self, max_portfolio_risk_pct: float = 0.01, max_leverage: int = 3):
        self.max_portfolio_risk_pct = max_portfolio_risk_pct
        self.max_leverage = max_leverage

    def validate_and_approve(self, order: TradeOrder, account_balance: float) -> bool:
        # Расчет риска на сделку
        risk_amount = abs(order.entry_price - order.stop_loss) * order.size
        allowed_risk = account_balance * self.max_portfolio_risk_pct

        if risk_amount > allowed_risk:
            logger.error(f"Order REJECTED: Risk {risk_amount:.2f} exceeds allowed {allowed_risk:.2f}")
            return False

        logger.info(f"Order APPROVED for {order.symbol}: Size {order.size}, Risk {risk_amount:.2f}")
        return True

# Пример использования
guardian = RiskGuardian(max_portfolio_risk_pct=0.01)
order = TradeOrder(symbol="ETH-PERP", side="BUY", size=1.5, entry_price=3100.0, stop_loss=3050.0)
is_approved = guardian.validate_and_approve(order, account_balance=50000.0)
```
